Кратко: в MVP не нужно дообучать LLM. Нужны инференс готовых FinBERT/RuBERT и обучение LSTM. Дообучение на разметке — это уже СРО3. Ниже — план на ~12–16 часов именно под часть Анастасии.

---

## Что сдаёшь (минимум для приёмки ИИ)

1. CLI score_sentiment — новость → score p_pos − p_neg → запись в БД / CSV  
2. Агрегация дневного индекса (хотя бы в pandas, view может сделать Асель)  
3. CLI train_lstm / predict — F=3 и F=4, naive baseline  
4. Папка models/ (веса + config.json + metrics.json)  
5. Числа: MAE, RMSE, directional accuracy, RMSE_rel — улучшил ли sentiment

Тикеры для старта: только SBER, потом при времени — остальные.

---

## Вечер 1 (3–4 ч) — «тональность без магии»

Цель: один скрипт, который ставит score новости.

1. Поставить: torch, transformers, pandas, scikit-learn (лучше CPU; GPU не обязателен).  
2. Взять готовые чекпоинты (как в плане):
   - RU: blanchefort/rubert-base-cased-sentiment
   - EN: ProsusAI/finbert  
3. Написать src/sentiment/infer.py:
   - очистка текста (простая);
   - детект языка (langdetect или эвристика «кириллица → ru»);
   - tokenize max_length=128;
   - score = p_pos − p_neg.  
4. Прогнать на 50 новостях из CSV/БД коллег → таблица sentiment_scores или scored.csv.  
5. Агрегация по дню+тикеру: среднее score (формулы 2.1–2.3 — упростить до mean, если нет весов).

Готово, если: на 50 новостях есть scores и дневной ряд для SBER.

Не трогать: разметку 400 новостей, fine-tune, кастомный head.

## День (6–8 ч) — LSTM F=3, потом F=4

Утро — данные и F=3

1. Взять свечи SBER (у Асель/из CSV): close, volume.  
2. Признаки: pt (цена), vt (объём), rt (return) — как в плане.  
3. Окна N=30, scaler только на train, split 70/15/15 по времени (не shuffle).  
4. LSTM: L=2, H=64, dropout=0.2, Adam, MSE, early stop, seed=42.  
5. Naive baseline: прогноз = вчерашняя цена (или return=0 — зафиксируй одно правило).  
6. Метрики на test: MAE, RMSE, DA, RMSE_rel vs naive.  
7. Сохранить в models/lstm_sber_f3/.

Готово к обеду, если: F=3 обучается end-to-end и пишет метрики.

После обеда — sentiment в модель (F=4)

1. Подтянуть дневной sentiment Sk,t, выровнять по датам (join, пропуски → 0 или ffill — одно правило в README).  
2. Та же архитектура, вход F=4.  
3. Сохранить models/lstm_sber_f4/ + сравнение метрик F=3 vs F=4 vs naive.  
4. CLI predict → таблица/CSV forecasts на t+1.

Готово к вечеру, если: есть численный ответ «sentiment улучшил / не улучшил» на SBER.

## Порядок зависимостей от команды

| Тебе нужно | Кто даёт | Fallback на 1 день |
|---|---|---|
| Свечи SBER ≥1–2 года | Асель / ETL | CSV с MOEX ISS вручную |
| Новости с датой+тикером | Асель / ETL | 50–200 строк в CSV |
| Таблицы БД | Асель | работай через CSV → потом вставите |

Не блокируйся на Postgres — сначала CSV, интерфейс БД можно тонким слоем в конце.

---

## Что говорить на защите «про LLM»

- Использованы предобученные FinBERT/RuBERT как энкодеры тональности (zero-shot / off-the-shelf).  
- Дообучение LLM отложено: нужна разметка ≥400 новостей (СРО3).  
- Основная обучаемая модель MVP — LSTM с/без дневного индекса тональности; гипотеза проверяется метриками.

Это честно и совпадает с планом.

## Риски за 1 день+2 вечера

| Риск | Что делать сразу |
|---|---|
| Нет новостей/свечей | Сгенерировать/скачать CSV самому в первые 30 мин вечера 1 |
| GPU нет / долго | CPU + batch маленький; FinBERT только на 50–200 новостей для демо |
| LSTM не учится | Упростить: 1 слой, H=32; главное — pipeline + метрики |
| Sentiment «не улучшил» | Это нормальный результат гипотезы — зафиксируй числа |
