# Краткая инструкция оператора — invest-ai

## 1. Запуск

```bash
cd invest-ai-platform
docker compose up -d
```

Открыть: **http://localhost:8000**

Просмотр БД (по желанию): **http://localhost:8080**  
System: PostgreSQL · Server: `db` · User/Pass/DB: `invest`

Остановка: `docker compose down`

---

## 2. Ежедневная работа в UI

1. Выбрать **тикер** (например SBER).
2. Нажать **«Полный пайплайн»** — или шаги по очереди:

| Кнопка | Что делает |
|---|---|
| 1. Свечи | Загрузка котировок с MOEX |
| 2. Новости | Сбор RSS |
| 3. Sentiment | Оценка тональности (FinBERT/RuBERT) |
| 4. Train LSTM | Обучение моделей F=3 и F=4 |
| 5. Predict | Прогноз цены на следующий торговый день (+ auto-sync в Postgres) |
| 6. Sync → Postgres | Ручной полный sync (обычно не нужен) |

Шаги **1–3 и 5** сами пишут CSV и сразу делают **auto-sync** в PostgreSQL (если БД доступна).
Кнопка 6 — запасной полный sync.

3. Смотреть **лог** внизу: дождаться «готово» (зелёный статус).
4. Проверить блок **«Прогноз t+1»**, **метрики**, график на тесте.

Train может занять несколько минут — не закрывать вкладку и не запускать второй пайплайн параллельно.

---

## 3. Как читать результат

- **Прогноз t+1** — цена закрытия и направление (↑ / ↓) на следующий торговый день.
- **F=3** — только цены; **F=4** — цены + тональность новостей.
- **RMSE_rel &lt; 1** — модель лучше наивного «завтра = сегодня».
- В метриках: улучшила ли тональность RMSE и долю верных направлений (гипотеза).

---

## 4. Типовые проблемы

| Симптом | Что сделать |
|---|---|
| UI не открывается | `docker compose ps`, затем `docker compose logs -f invest-ai` |
| Postgres: нет связи | Дождаться healthy у `db`, перезапуск: `docker compose restart` |
| Нет моделей / ошибка sentiment | Проверить, что на хосте есть HF-модели по пути из `config/settings.yaml` |
| Пустой прогноз | Сначала Train, потом Predict |
| Долго «выполняется» | Смотреть лог; Train/Sentiment — нормально долго |

---

## 5. Важно

- Это **аналитический MVP**, не торговый робот и не инвестрекомендация.
- Данные пишутся в CSV (`data/`) и **сразу** в Postgres (auto-sync после шагов). CSV — кэш/отладка.
- Отключить auto-sync: `AUTO_SYNC_DB=0` или флаг `--no-sync` у CLI-скриптов.
- Пароли БД по умолчанию только для локальной среды (`invest` / `invest`).
